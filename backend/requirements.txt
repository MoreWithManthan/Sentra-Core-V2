# COMPATIBILITY NOTE — yara-python and Python version:
#   yara-python (latest: 4.5.4) ships prebuilt wheels for CPython 3.9-3.13 on
#   Windows/macOS/Linux. There is currently NO prebuilt wheel for Python 3.14 yet.
#   On Python 3.14, pip falls back to a source build, which requires a C++ toolchain
#   (on Windows: "Desktop development with C++" from the Visual Studio Build Tools).
#   The environment marker on the yara-python line below tells pip to skip it
#   entirely on 3.14 rather than attempting — and failing — that source build.
#
# IMPORTANT — a single failing package aborts the WHOLE install, not just itself:
#   If any one line in this file fails to build (as yara-python did on 3.14
#   before the marker below was in place), `pip install -r requirements.txt`
#   aborts as a unit — NONE of the other packages get installed either, even
#   though their wheels resolved and downloaded fine moments earlier. If you
#   ever see ModuleNotFoundError for something totally unrelated (psutil,
#   fastapi, etc.) right after a build failure earlier in the same log, this
#   is almost always why: re-run the full `pip install -r requirements.txt`
#   after fixing whatever failed, don't just `pip install` the missing piece
#   by hand — see the WARNING below for why that shortcut can bite you too.
#
# WARNING — do not `pip install dotenv` to "fix" a missing python-dotenv:
#   `dotenv` and `python-dotenv` are two different, unrelated PyPI packages
#   that both install a top-level module literally named `dotenv` — installing
#   both lets one silently overwrite the other's files on disk, and whichever
#   "wins" determines what `from dotenv import load_dotenv` actually imports.
#   The package this project needs is `python-dotenv` (already listed below).
#   If you've accidentally installed the wrong one: `pip uninstall dotenv -y`,
#   then `pip install --force-reinstall python-dotenv`.
